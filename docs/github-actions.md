# GitHub Actions Build

ClientCore includes workflows for building the plugin and publishing the documentation wiki.

## Build Workflow

File:

```text
.github/workflows/build.yml
```

The build workflow runs on every push, pull request, and manual dispatch.

It performs these steps:

1. Checks out the repository.
2. Installs Temurin Java 25.
3. Caches Gradle dependencies.
4. Runs `./gradlew clean build`.
5. Uploads jars from `build/libs/` as a GitHub artifact.
6. Optionally posts Discord build status if the repository secrets are configured.

## Discord Build Notifications

The workflow reads these optional secrets:

```text
DISCORD_WEBHOOK_URL
DISCORD_WEBHOOK_THREAD_ID
```

If `DISCORD_WEBHOOK_URL` is empty, the Discord notification steps are skipped and the build still runs normally.

## Artifact Output

The shaded plugin jar is generated by the Gradle `shadowJar` task and uploaded as the `ClientCore-Build` artifact.

Use the `*-all.jar` file for servers because it includes bundled runtime dependencies such as PacketEvents.

## Pages Workflow

File:

```text
.github/workflows/pages.yml
```

The Pages workflow publishes the `docs/` folder through Jekyll when documentation changes are pushed to `main` or
`master`.

Repository Pages must be enabled in GitHub settings and configured to use GitHub Actions as the source.

## Local Verification

Use the same build command locally before pushing:

```bash
./gradlew clean build
```

On Windows:

```powershell
.\gradlew.bat clean build
```
